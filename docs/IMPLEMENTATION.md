# 当前实现与整体优化依据

更新：2026-10-19，板端输入路径v4。本文是**当前软件如何计算、数据如何流动、优化到了哪里**的总览；v4开发回归与实板验收分别记录，未测的收益不作估计。

文档分工：[模型功能](MODEL.md)说明24个模块的用途；本文说明实现和数据通路；[334节点CSV](operator-audit.csv)列出每次运算的形状、公式、布局、源码及候选问题；[性能评估](TUNING.md)记录实测、计时边界和对比方法；[README](../README.md)只提供现场入口。[平台与同步](BOARD.md)、[PCIe协议](PCIE.md)、[诊断](DIAGNOSTICS.md)分别维护接口契约。

## 1. 固定配置与完整链路

YOLO26n，一对一分支，416×416、batch=1、COCO80；完整334节点、21类算子。只维护RVV+AMU正式整网，标量用于数值参考；INT8、跟踪和默认NMS不在本轮范围。

```text
Linux host读取视频/摄像头
 → OpenCV等比例缩放、补114、BGR转RGB、除255、NCHW FP32
 → PCIe写入DDR输入区，最后提交session/帧号/长度/CRC
 → N550校验输入，依次执行334节点（含框解码及两次Top-K）
 → 输出CRC/缓存发布后提交DONE
 → host读回候选、核对会话及CRC，score>0.25过滤、还原并裁剪坐标
 → OpenCV绘框与显示，保存源帧、检测PNG、原始候选和demo.mp4
```

输入为 `[1,3,416,416]` FP32，2,076,672字节；输出为 `[1,300,6]` FP32，7,200字节，每行 `x1,y1,x2,y2,score,class`，坐标相对于416输入图。UART只发调试文字。程序与原始FP32权重一起加载BIN一次，后续帧复用程序、权重、arena及临时区；只允许一帧在途。

## 2. 存储与形状

| 区域 | 大小/布局 | 用途与生命期 |
|---|---|---|
| 原始常量 | 9,678,644字节，普通DDR | 冻结FP32权重、bias及索引常量，随BIN部署 |
| FP16预打包权重 | 预留5MiB，实际5,033,984字节 | READY前转换94层共2,391,664个有效权重；此后只读 |
| arena | 7,614,720字节，CLP区 | 按张量生命期复用；张量offset/形状见CSV |
| conv_scratch | 原512KiB CLP预留保持不变 | union：RVV分组卷积存FP32 im2col；AMU输入最多用前256KiB存FP16 |
| 历史左右输入块 | 各2KiB，CLP区 | 保留地址布局及回归旧内核；正式AMU输入读取预打包区和conv_scratch |
| RVV地址元数据 | 3×4096×4=49,152字节，普通DDR | 缓存最近的K索引、核行和核列；输入/核形状变化时重建，非模型权重 |
| 诊断/计时/邮箱 | 普通DDR | 地址由固件发布，绑定会话与帧号；接口见专门文档 |

CLP总预留仍为8,143,104字节；RVV使用 `0x1000…` 别名，AMU/标量/PCIe使用 `0xF000…` 全局地址。普通DDR的代码、BSS等必须位于 `0x80000000–0x81FFFFFF` 独占区并避开邮箱。实际符号见当前 `firmware/pcie-symbols.txt`，不能沿用旧ELF地址。

特征图为NCHW，权重为OIHW。普通卷积映射为 `W[M,K] × X[K,P] → Y[M,P]`，`M=Cout`、`K=Cin×Kh×Kw`、`P=Hout×Wout`；AMU按M/N/K各最多32分块，这里的N是输出空间位置数，不是特征图batch。

## 3. 普通卷积：RVV准备输入，AMU计算

源码：[模型调度](../yolo26_riscv/accel_model.c)、[RVV打包](../yolo26_riscv/amu_input_rvv.c)、[整数FP16转换](../yolo26_riscv/amu_half_rvv.h)、[AMU执行](../yolo26_riscv/amu.c)。

1. **启动准备权重**：从FP32常量按现有 `amu_half` 最近偶数规则转FP16，排为 `[ceil(M/32),ceil(K/32),32,32]`，清零无效位置并clean到DDR。每帧不再转换权重。
2. **选择≤32个输出位置**：从位置推导卷积窗口原点。K按输入通道、核行、核列排列，保持原乘加顺序。
3. **RVV提取与转换**：沿K用 `e32,m2` 批量计算边界掩码和字节索引，masked gather只读取有效位置，无效lane显式置零；用整数移位、加法、掩码实现FP32→FP16最近偶数舍入，包括正负零、次正规数和舍入进位。不使用向量FP16算术，也不改变浮点舍入CSR。
4. **直接生成输入块**：整数窄化为 `e16,m1`，连续写入 `[ceil(K/32),32个位置,32个K]`。不足32的位置和K尾部补零。原FP32临时矩阵和重复输入转换已移除；1×1卷积同样复用这一输入块。
5. **所有输出通道共用**：每个M32权重块读取同一份输入；每个输出从零开始，按原K32指令顺序累加。末指令使用实际K长度，完成后存FP32结果，最后独立FP32加bias。
6. **安全复用**：全部M块和输出存储完成后，才覆盖scratch处理下一个空间块；保留现有AMU完成等待和输出交接。

例：节点16，输入 `[1,64,104,104]`，权重 `[64,64,3,3]`，输出 `[1,64,52,52]`，M=64、K=576、P=2704。每个32位置块占 `18×32×32×2=36KiB`，输出通道0–31和32–63共用；此前需要FP32 im2col 72KiB，再重复转FP16。

一帧94层共有5,710个空间块、22,583,808个逻辑输入值；含tile补零共24,632,320个FP16存储槽位。输入准备仍需每帧执行。元数据只缓存最近形状，不等于所有层索引在启动时一次准备好。

超过当前EI32索引范围的通用形状保留标量打包回退；冻结模型94层均使用RVV路径，开发整图回归检查实际RVV调用数。原标量打包保留为位模式参考，不新增纯RVV整网产品。

## 4. 缓存与执行顺序

- 节点边界先clean其输入，保证RVV CLP别名读取最新DDR；本轮沿用这个契约，未删除边界维护。
- 预打包权重只在启动时发布，此后只读；私有索引元数据在形状变化、标量重建后clean，供RVV读取。
- RVV写输入块前，对整个64字节对齐块flush/移交；通过CLP别名写入，完成后fence/invalidate并归还所有权，再让AMU读取全局地址。期间不混入标量缓存写。
- AMU输入块在同步调用返回前只读。每条指令保留完成等待，AMU输出及RVV bias保留既有缓存交接。
- fence约束顺序，不能替代CBO或AMU完成语义。标准与intrinsic依据：[RISC-V V 1.0](https://docs.riscv.org/reference/isa/unpriv/v-st-ext)、[Vector C Intrinsics](https://github.com/riscv-non-isa/riscv-rvv-intrinsic-doc)。具体平台约束见[BOARD](BOARD.md)。

## 5. 全部21类算子的当前路径

| 操作/节点数 | 运算和当前实现 | 后续审查重点 |
|---|---|---|
| CONV /102 | 94个普通卷积：RVV输入+AMU FP16；8个深度卷积：FP32 im2col+RVV顺序乘加+bias | RVV输入准备实测；深度卷积专用路径 |
| SILU /87 | RVV FP32计算x×sigmoid(x)，使用既有指数近似 | 近似与除法成本，数值规则需保留 |
| ADD /21 | C生成广播索引，RVV相加；本图同形状 | 连续加载替代索引生成 |
| SUB /1 | 同上，逐元素相减；本图同形状 | 同形状快速路径 |
| MUL /3 | C生成广播索引，RVV相乘 | 同形状或标量广播路径 |
| COPY /32 | 当前图输入输出同址，零拷贝视图 | 已实现；保持根张量生命期 |
| SLICE /28 | 按轴截取并复制，FP32用RVV | 20个连续子视图需联动生命期和guard |
| CONCAT /24 | RVV分段复制，沿指定轴合并 | 考察生产者直接写入目标区 |
| POOL /3 | RVV最大池化，边界外不参与 | 连续窗口读取，不能把边界补0当最大值候选 |
| NEAREST /2 | RVV复制，上采样H/W各2倍 | 连续行写入及消费者布局 |
| PERMUTE /5 | C生成轴重排索引，RVV加载 | 连续分段及避免物化的消费者支持 |
| EXPAND /10 | 全部物化；FP32用RVV，INT64用标量 | 8个恒等别名、2个索引展开与Gather融合 |
| BMM /4 | RVV沿列并行，各输出按K顺序独立乘法/加法 | 多行复用B加载，不能直接换FMA |
| SOFTMAX /2 | 按既有最大值、指数近似、求和及归一化顺序 | 归约和近似更改需另立数值方案 |
| SIGMOID /1 | RVV既有指数近似与除法 | 同输入效果及成本 |
| MAX /1 | 标量沿轴求最大值和首个索引 | 保留同分规则 |
| TOPK /2 | 标量维护前300有序候选，同分小索引优先 | 堆/选择算法须保持完整排序语义 |
| GATHER /3 | FP32用RVV索引读取，INT64用标量 | 与Expand合并，整行搬运 |
| REMAINDER /1 | 标量INT64取余，拆分类别索引 | 整数及负数规则 |
| FLOORDIV /1 | 标量INT64向下整除，拆分候选位置 | 同上 |
| CAST /1 | 标量类型转换，将索引整理为输出 | 类型、范围及顺序 |

深度卷积输入 `[1,C,H,W]`、权重 `[C,1,3,3]`，每通道独立九项乘加；当前仍按通用分组循环生成 `9×32` FP32矩阵，再调用RVV矩阵乘，保留独立乘法和加法。节点274、278分别C=64、80，H=W=52；报告统一标作conv，并不表示走AMU。

Attention的4个BMM为两个模块各一次相关性和内容汇总，分别涉及 `[2,169,32]×[2,32,169]`、`[2,64,169]×[2,169,169]`。分类、框解码和Top-K均保留在334节点图中，host只做阈值筛选、坐标还原及绘图。

## 6. 后续优化如何决策

已完成：COPY别名、启动权重预打包、直接FP16窗口生成与M块复用；当前新增RVV输入版，收益等待同三帧实板测量。实测表和各版含义只在[TUNING](TUNING.md)维护。

下一轮按实际周期排序：深度卷积直接RVV窗口；同形状Add/Sub；Expand/Gather；Slice子视图；BMM多行共享；跨层融合及AMU寄存器/双缓冲。上述均为候选，需要单独确定实施范围，不因写入本文自动实施。`other_compute`尚未逐项归因，不能全部算作可删除开销。

输入准备与AMU等待不是完整分离的硬件占用指标，不能用matrix_wait的小数值推导AMU利用率。PCIe工具累计时间与板端计算重叠，不能相加当作额外串行耗时。模型精度方向与算力方向分开验收，少框不代表准确率提高。

## 7. 节点表与验证依据

```bash
# 本地或host仓库根目录：从冻结图更新334节点CSV与源码哈希快照
python3 tools/build_operator_audit.py

# 检查源码或冻结图变化后节点审查资料是否过期；不访问板子

```

[operator-audit.json](operator-audit.json)绑定冻结模型哈希、CSV哈希和相关源码LF归一化哈希。脚本的实现说明是维护的静态审查，不能自动证明任意新代码正确；修改内核时需更新说明、重生成并核验。

开发验证覆盖独立IEEE binary16与标量位模式、所有94层输入形状、边界/跨行/尾块复用、异常值、VLEN128/512、不同frm及矩阵/卷积顺序；完整BUS使用正式启动和PCIe路径，核对最终7200字节和5710次RVV输入准备。QEMU统一RAM不能证明实板缓存与速度，发布后仍需同三帧 `VIDEO CHECK PASSED` 与菜单18计时；无需重新采集全部节点。
