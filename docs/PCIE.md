# PCIe 接口与同步约定

本页只维护DDR收发协议、状态机与失败语义。运行命令见[OPERATIONS](OPERATIONS.md)，加载与缓存前提见[BOARD](BOARD.md)，输入张量及候选字段见[IMPLEMENTATION](IMPLEMENTATION.md#1-固定配置与完整链路)。UART不参与本协议。

## 传输与同步约定

- 已确认：CPU运行期间可访问DDR，`pbcopy`成功返回表示写入已到DDR；地址换算为 `PCIe地址=CPU地址−0x80000000`。平台说明目前无额外地址对齐/长度限制。
- 写命令：`pbcopy -d 文件:PCIe地址`；读命令：`pbload -d 输出文件:PCIe地址:字节数`。host在许可工作目录使用短临时文件名，检查失败文字、退出码和长度，自动清理文件；不把长输出路径交给现场pbload。
- 本模型输入2,076,672字节、结果7,200字节，均为小端FP32；以固件描述发布的地址/长度为准，不向RVV别名写入。
- 仅一个host控制程序；本机文件锁防止重复启动。其他PCIe工具、另一账户或其他机器不能同时改写这些DDR区域。

固定接口位于现有32 MiB预留DDR内部，不使用另一个仓库的输入、权重和结果区：

| 区域 | CPU地址 | PCIe地址 | 字节数/写入方 |
|---|---|---|---|
| 固件描述 | `0x81F00000` | `0x01F00000` | 64，板端 |
| 命令正文 | `0x81F00040` | `0x01F00040` | 64，host |
| 提交序号 | `0x81F00080` | `0x01F00080` | 64，host，仅首个uint32有效 |
| 处理状态 | `0x81F000C0` | `0x01F000C0` | 64，板端 |

输入/输出地址由固件描述发布，当前位于已批准的 `0xF0000000–0xF0FFFFFF`（PCIe偏移 `0x70000000–0x70FFFFFF`）。诊断、计时表、邮箱及栈仍在原32 MiB区。旧诊断816字节，新诊断832字节追加计时表地址/长度；新Host兼容两者，布局见[诊断](DIAGNOSTICS.md)。host验证大小、范围和64字节对齐，拒绝RVV别名；保留旧正常DDR描述兼容性。host/板端写区分占缓存行，避免维护覆盖另一方数据。

请求options允许位1（值2，逐节点UART日志）、位2（值4，中间有限值检查）、位3（值8，逐节点采集），其他位拒绝。普通验证组合为6，自动采集默认为12。接口为小端、版本1，描述和状态magic为 `Y26P`；描述、命令、状态均为前60字节CRC32存于最后4字节，布局见 `board/pcie.h`。

1. 板端初始化接口、自测，flush输入区后发布READY。host提交OPEN，以随机64位session建立会话；帧号为64位，命令序号为非零32位。
2. host写完输入，再写带长度/CRC的RUN正文，逐字节读回确认正文，最后写提交序号。正文未验证成功不提交，输入错误由板端CRC拦截。
3. 板端invalidate提交区及正文；相同提交序号不重复执行。核对会话、长度、输入CRC后运行模型。
4. 板端clean结果，flush即将交还host的输入缓存行，完成fence后发布DONE、帧号、结果长度和CRC。host读结果并核对CRC/有限值/类别，以及读取前后状态一致；完成后才提交下一帧。中间张量有限值检查可用 `--check-intermediates` 开启。

状态：0 BOOT、1 READY、2 BUSY、3 DONE、4 ERROR、5 NODE（采集暂停）。错误码：`0x40`命令CRC/格式、`0x41`会话、`0x42`输入CRC、`0x43`模型执行失败、`0x44`host取消采集；模型详细错误仍在 `board_diag`。输入/输出可在模型arena内复用内存，host不得在BUSY或NODE时写输入，也不得在下载旧结果前开始写下一帧。

## 可选节点采集

固件描述的 `reserved` bit0表示支持采集，`reserved2`发布普通DDR中的64字节对齐快照地址（uint32，当前地址低于4 GiB）。未启用options=8时不扫描或等待节点数据，普通图片/视频入口保持原协议。

启用后，每节点记录输入计算前CRC，运算后clean输入/输出并记录CRC，再发布512字节快照和NODE状态。快照头64字节包含版本、节点/算子、session/frame/sequence、输入/输出数、token=node+1及options；接着是最多4输入、2输出的64字节描述（ID、类型、形状、全局地址、字节数、constant、前后CRC）。未保留输出的ID为-1。尾部含AMU flags、节点周期和phase；前508字节CRC存最后4字节。状态的output_bytes/output_crc此时对应快照，detail为节点编号。

host核对身份、图描述、快照/张量CRC和读取前后状态。读取完成发送命令3 ADVANCE，或命令4 ABORT；input_bytes=0，input_crc字段在这两个命令中携带token，session/frame/options须与当前采集一致。沿用正文读回后提交新序号的机制；重复或旧提交不生效。ADVANCE恢复BUSY，最终仍按普通协议发布7200字节DONE；ABORT发布ERROR/0x44，后续OPEN可建立新会话。

暂停期间只允许确认或取消，不接受新帧和OPEN。输入内存可能被当前输出复用，前后CRC不同并不必然是故障；host可从此前完整输出重建该输入并核对计算前CRC。正常异常/退出尽力取消；进程强杀可通过 `node_capture.py --recover-paused` 在获取互斥锁、确认提交已消费后终止旧会话。暂停没有板端自动超时，核心须保持运行。

## 失败与复验

`--infer-timeout` 默认900秒，覆盖单帧传输和推理；`--tool-timeout` 默认30秒限制一次工具调用；`--poll-interval` 默认0.1秒。轮询开销和实际吞吐待板上测量，不预先承诺5 FPS。

工具非零退出立即报错，退出0仍检查实际读回长度、命令读回、输入/结果CRC与帧号，不只相信日志中的success。状态CRC不匹配可能是发布中读到半条记录，在总超时内重读。命令、退出码、工具输出尾部、各阶段耗时和失败信息均写入日志；完成/失败时经PCIe读取固定诊断快照；运行进度由调试UART输出文字，`--board-trace`启用逐节点日志。

普通模式取消/超时停止host收发，不复位板子，也不能中断已经开始的推理；采集模式可在下一个NODE暂停点取消。同一个失败会话不能再提交帧；重新连接会先等旧命令结束。若内核驱动调用本身不可中断，或板端始终BUSY，由同事检查/恢复平台后再启动。板端trap尽力发布ERROR和诊断；无法返回的总线/AMU指令只能靠host超时及同事调试器定位。

验证证据与结论边界见[VALIDATION](VALIDATION.md)；不能仅凭工具退出0或状态DONE证明数值正确。
